# secure-access-helper

Автоподключение к корпоративному VPN-клиенту на macOS через UI scripting.
Хранит пароль в Keychain, заполняет форму авторизации скриптом, автоматически
жмёт «Подтвердить» и обрабатывает диалог «Transfer Logon» (если активна сессия
с другого устройства).

## Зачем

VPN-клиент при каждом подключении просит пароль (даже если выбран чекбокс
«Сохранить настройки» — сохраняется только логин/подключение, не пароль).
Скрипт убирает ручной ввод.

## Состав

| Файл                          | Назначение                                              |
| ----------------------------- | ------------------------------------------------------- |
| `install.sh`                  | Установка на новой машине                               |
| `uninstall.sh`                | Снятие: симлинк из PATH, конфиг, запись в Keychain      |
| `setup.sh`                    | Сохраняет логин (конфиг) и пароль (Keychain)            |
| `connect.sh`                  | Главная точка входа: запуск + ретраи при зависании      |
| `fill.applescript`            | UI scripting: клики, ввод пароля, обработка sheet'ов    |
| `debug-inspect.applescript`   | Дамп AX-дерева окон — нужен только для отладки          |

## Требования

- macOS (тестировалось на 15.x)
- Установленный VPN-клиент (имя приложения и сценарий UI заданы в
  `fill.applescript` через `property kAppName`).
- В приложении хотя бы раз вручную добавлено и выбрано рабочее подключение
  в дропдауне Connection на главном экране.

## Установка на новой машине

```bash
git clone <repo-url> ~/Projects/secure-access-helper
cd ~/Projects/secure-access-helper
./install.sh
```

`install.sh` идемпотентный — при повторном запуске пропускает уже выполненные
шаги или предлагает их пересоздать. Шаги:

1. Проверяет наличие целевого приложения в `/Applications`.
2. Делает скрипты исполняемыми.
3. **Accessibility-права.** Если их нет — открывает Системные настройки и
   подсказывает имя текущего терминала (определяет автоматически через дерево
   процессов). После галки делает реальную проверку через тестовый AppleScript —
   пока права не выданы, не идёт дальше.
4. **Креды.** Если ничего не сохранено — запускает `setup.sh` (спросит логин
   и пароль):
   - **Пароль** → macOS Keychain (`service=secure-access-helper`)
   - **Логин**  → `~/.config/secure-access-helper/account` (0600)

   Пароль в открытом виде нигде на диске не оседает. Если креды уже есть —
   спрашивает «Перезаписать?».
5. **Команда `secure-access-helper`.** Создаёт симлинк на `connect.sh` в первом
   подходящем месте: `/opt/homebrew/bin` (Apple Silicon, обычно writable без
   sudo) или `/usr/local/bin` через sudo.

При **первом** запуске `secure-access-helper` macOS дополнительно покажет
диалог Keychain Access с вопросом разрешить ли `security` доступ к записи —
жми **Always Allow**.

## Использование

```bash
secure-access-helper                                  # если ставил симлинк
~/Projects/secure-access-helper/connect.sh           # прямой вызов
```

Что происходит:
1. Активирует целевое приложение (запускает, если не запущено).
2. Если уже висит модальный sheet (забытый Transfer Logon и т.п.) —
   разруливает его сразу.
3. На главном окне:
   - Если есть **Disconnect** — VPN уже подключён, скрипт выходит с
     `alreadyConnected`.
   - Иначе жмёт **Connect** (внутри WebView обычно реализован как `AXLink`).
4. Дожидается окна авторизации, рекурсивно ищет `AXSecureTextField` в HTML-форме
   и набирает пароль из Keychain (предварительно убедившись, что приложение
   реально стало frontmost — иначе пароль улетел бы в терминал).
5. Жмёт submit (`AXLink` или `AXButton` с подходящим именем).
6. Если появляется sheet «Transfer Logon» — автоматически жмёт **Transfer**.
7. Если за 30 секунд auth-окно не исчезло — корректный quit + retry
   (до 3 попыток).

### Привязка к хоткею

После `install.sh` команда `secure-access-helper` доступна глобально. Дальше —
Raycast Script Command, ярлык в **Shortcuts.app** с действием
«Run Shell Script: `secure-access-helper`», или собственный шорткат в твоей
системе хоткеев.

## Конфигурация

Аккаунт берётся в таком порядке (первое непустое значение):

1. Переменная окружения `SECURE_ACCESS_ACCOUNT`
2. Файл `~/.config/secure-access-helper/account`
3. Фолбэк: парсинг `security find-generic-password -s secure-access-helper`

Важно: `SECURE_ACCESS_ACCOUNT` влияет только на `connect.sh`. `setup.sh` при
перезапуске с этой переменной просто подставит её как значение по умолчанию
в промпте логина.

Имя целевого приложения, имя сервиса в Keychain и список имён кнопок — в начале
`fill.applescript` (свойства `kAppName`, `kKeychainService`, `kConnectNames`, …).
Под другой VPN-клиент достаточно поменять `kAppName` и при необходимости —
списки имён кнопок submit/disconnect.

## Что если ломается

1. **«osascript is not allowed assistive access»** — терминалу не дали
   Accessibility-права. Перезапусти `install.sh` или вручную: Системные
   настройки → Конфиденциальность и безопасность → Универсальный доступ.
2. **`ERROR: не стал frontmost`** — фокус не успел переключиться. Проверь, что
   не работаешь в фуллскрин-режиме другого приложения, и повтори.
3. **`ERROR: AXSecureTextField не найден в auth-окне`** — структура AX-дерева
   могла измениться (новый билд клиента, другая локализация). Запусти отладочный
   дамп пока auth-окно открыто:

   ```bash
   osascript ~/Projects/secure-access-helper/debug-inspect.applescript > ~/axdump.txt
   ```

   Сравни вывод с тем, что ищет `fill.applescript`.
4. **Пароль набирается мусором** — у тебя активна нелатинская раскладка
   клавиатуры в момент логина. `keystroke` в AppleScript зависит от текущего
   layout. Перед запуском переключись на ABC/EN.
5. **Клиент висит после ввода пароля** — `connect.sh` это сам ловит и делает
   quit + retry. Если через 3 попытки не зашло — проблема не в автоматизации.

## Безопасность

- Пароль хранится в macOS Keychain (та же защита, что у браузеров и системных
  учёток).
- AppleScript читает пароль через `security find-generic-password -w` в момент
  логина и передаёт его в `keystroke` — на диск не пишется, в `ps` не светится.
- Перед `keystroke` скрипт проверяет, что целевое приложение реально стало
  frontmost (`frontmost of process is true`). Если нет — выходит с ошибкой и
  **не вводит пароль**, чтобы он не улетел в терминал/другое приложение.
- При неудаче с поиском secure-поля скрипт **не** делает фолбэк на обычное
  text field (иначе пароль мог бы оказаться в видимом поле логина как plaintext).
- Логин (`account`-файл) хранится с правами 0600 в `~/.config/`.

## Перенос на новый компьютер

1. `git clone` репо.
2. `./install.sh`.
3. Один раз пройти диалоги разрешений (Accessibility + Keychain Always Allow).

Keychain не переносится автоматически — пароль нужно ввести заново через
`setup.sh` (или импортировать связку ключей через Migration Assistant).

## Снятие

```bash
~/Projects/secure-access-helper/uninstall.sh
```

Уберёт симлинк `secure-access-helper` из всех возможных локаций
(`/opt/homebrew/bin` и `/usr/local/bin`; sudo по необходимости), спросит
подтверждение для удаления конфиг-файла и записи в Keychain. Сам репозиторий
не трогает.
